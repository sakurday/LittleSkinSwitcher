> 我想实现一个Minecraft的模组，在游戏内即可实现正版账户和littleskin皮肤站的的切 
  换。                                                                          
                                                                                
  - 游戏版本：Minecraft Java版                                                  
  26.1.2。在你的知识库内可能没有这个版本，但是这个版本如今确实存在。            
                                                                                
  - 模组加载器：Fabric                                                          
                                                                                
  - 模组为仅客户端模组                                                          
                                                                                
  # 具体内容                                                                    
                                                                                
  使用这个模组，将会默认玩家在启动器使用正版登录。                              
                                                                                
  进入游戏后，在服务器列表界面左上角添加按钮"配置LittleSkin"，在这里可以输入lit 
  tleskin的账号和密码。                                                         
                                                                                
  默认状况下，进入所有服务器都使用正版登录，也就是玩家不需要进行额外操作。      
                                                                                
  在多人游戏界面，与服务器相关的按钮的右下角添加"使用LittleSkin"按钮。如果某个  
  服务器要求使用littleskin登录，玩家可以在服务器列表选中这个服务器，这样会默认  
  每次进入这个服务器都会使用littleskin登录。同时在服务器列表为这个服务器添加标  
  记，让玩家知道这个服务器将使用littleskin登录。                                
                                                                                
  # 注意事项                                                                    
                                                                                
  模组构建完成后你无须你测试，只需要告诉我构建完成，文件在哪，然后我会自己去测  
  试，然后把测试结果告诉你。

  使用方式

  1. 进入多人游戏界面，左上角出现 「配置 LittleSkin」 按钮 → 输入 LittleSkin
  账号（邮箱）和密码 → 点「登录 / 保存」。
  2. 每个服务器条目右下角有 「使用 LittleSkin / 使用正版」
  切换按钮：点了之后该服务器变成橙色标记，以后每次进这个服务器都自动用
  LittleSkin 登录；不点的一律走正版登录。
  3. 标记会按服务器地址持久化到 config/littleskin-switcher.json。

  实现要点（供你参考）

  - 26.1.2 这个版本有几个特殊之处，我做了针对性处理：
    - Fabric 官方还没有 26.1.2 的 Yarn 映射（meta API 返回空），而且 26.1.2
  的客户端 jar 本身就已是官方反混淆命名（intermediary 为 0.0.0
  恒等映射）——所以整个模组直接用 mojmap 官方类名编写，Mixin 无需 refmap
  也能按官方名直接匹配。
    - MultiplayerScreen 已改名为
  JoinMultiplayerScreen；服务器条目从旧的按钮控件改成了 extractContent 延迟渲染
  + OnlineServerEntry 精灵图点击模型，切换按钮和标记就是在这一层画的。
    - 会话结构大改：登录握手不再用 GameProfile 而是 joinServer(UUID, token, 
  serverId)，且从 Minecraft.services().sessionService() 实时读取。我通过
  @Redirect 把握手时的 join 请求在 LittleSkin 模式下转发到 auth.littleskin.cn 的
  Yggdrasil API，并在进入服务器前用 Mixin accessor 把 Minecraft#user 切换为
  LittleSkin 会话、返回服务器列表时还原正版。
  - 认证走标准 Yggdrasil 流程：authenticate → refresh →
  sessionserver/join，token 失效时自动用保存的密码重新认证。
  - 我用 genSources 反编译了真实的 26.1.2
  源码逐个核对过所有类名/方法签名，编译期 Mixin 注解处理器也校验通过。

● 改一个地方就够：gradle.properties 里的 mod_version。

  # gradle.properties 第 14 行
  mod_version=0.1.0

  改成新版本号（如 0.2.0）后重新 ./gradlew build，会自动影响两处，都不用手动改：

  1. jar 文件名：littleskin-switcher-0.2.0.jar（archives_base_name +
  版本号拼出来的）
  2. fabric.mod.json 里的版本：那行 "version": "${version}" 是占位符，构建时由
  build.gradle 的 processResources 自动替换成 mod_version 的值——所以不要去改 
  fabric.mod.json 里的 ${version}，否则会冲突。

  具体链路：
  gradle.properties: mod_version=0.1.0
          ↓ (build.gradle: version = project.mod_version)
  build.gradle 传给 processResources
          ↓ (expand "version")
  fabric.mod.json 里 ${version} → 实际版本号

  改完 jar 名会变，记得新 jar 替换 mods
  里的旧文件（旧的可以删掉，避免版本混乱）。版本号建议用语义化版本，比如加功能用
  0.2.0、修 bug 用 0.1.1。
